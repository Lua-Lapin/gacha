# ギャラリー公開の Cloudflare 移行 設計

日付: 2026-11-24
状態: 承認待ち

## 目的

- ギャラリーを独自ドメインのちゃんとした置き場から出す。
- 公開のたびに GitHub のビルドを待つのをやめる。公開は画像を送るだけで終わらせる。

**やらないこと**: ガチャ本体・APIのクラウド化、git 履歴（426MB）の書き換え、リポジトリの非公開化、ギャラリーの見た目変更、画像の縮小・形式変換。

**これでは失敗**: 公開に git push やビルドが要る／X に投稿済みのリンクが切れる／APIキーや未公開画像が外に出る。

## 検討した方式

| 方式 | 得失 | 判断 |
|---|---|---|
| A. Worker + R2、公開はアップロードのみ | 公開が速く同一ドメイン。小さな Worker が要る | **採用**（ユーザー選択） |
| B. Pages 静的HTML + R2 画像専用ドメイン | Worker 不要。公開のたびにビルド、CORS 対応が必要 | 不採用 |
| C. 全部 R2 | index.html の返却などの仕組みが結局要る | 不採用 |

## 構成

独自ドメインはユーザーが契約し、Cloudflare に追加してある前提。以下 `<ドメイン>`。

| パス | 返すもの |
|---|---|
| `/`, JS など | ビルド済みビューワー（Workers 静的アセット） |
| `/images/<id>.png` | R2。`max-age=31536000, immutable` |
| `/manifest.json` | R2。`no-store` |
| `/card/<id>.html` | manifest から Worker がその場で生成（既存 `cardPageHtml` を再利用） |
| 上記以外 | 404 |

- R2 バケットは非公開。Worker のバインディング経由だけで読む。読めるのは `images/<数字>.png` と `manifest.json` のみ。GET / HEAD のみ受ける。
- カードの絶対URLはリクエストの origin から作る。manifest に無い id は 404。
- ビューワーのツイートリンクは `location` を基準に作る。固定の `BASE` は廃止する。
- `gallery/dist` に画像と manifest を含めない。`gallery:build` は `publicDir` を無効にし、`gallery:dev` では今まで通り手元の `gallery/public` を使う。

## 公開の流れ（`POST /api/publish`）

1. 未公開のうちファイルがあるものを、id 順に R2 へ送る。
2. 全画像が成功したら、manifest を**最後に**送る。
3. DB を公開済みにする。

- 途中で失敗したら未公開のまま残す。再実行は同じキーへの上書きなので安全。
- **送る manifest は「公開済み + 今回公開分」だけで作る**。手元の manifest.json は未公開分も含むため、そのまま送らない。
- ファイルが消えている行は今まで通り公開済みにして詰まりを防ぐが、manifest には載せない。
- 同時に2回実行されないよう、公開中の再要求は 409 で断る。
- R2 への送信は S3 互換 API を使う。署名は `aws4fetch`（小さい依存）で行う。
- ボタン文言は「一括コミット＆プッシュ」から「公開する」に変える。レスポンスの `committed` は互換のため残す。
- git を呼ぶ処理（`defaultRunGit`、`publishPending` の git 部分）は削除する。

## 設定

`server/.env` に `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`（値はユーザーが入力）。キーは対象バケットだけの読み書き権限にする。`.env.example` に項目名だけ足す。
`wrangler.jsonc` に Worker 名、R2 バインディング、アセット、`<ドメイン>` のルートを書く（秘密なし）。wrangler は devDependency とし、ログインはユーザーが行う。

## コマンド

- `npm run gallery:deploy`: ビルドして `wrangler deploy`。見た目やガチャのコードを変えたときだけ使う。
- `npm run gallery:migrate`: 既存画像と manifest を R2 に一括送信する。再実行できる。

## 移行の手順

1. ユーザー: ドメイン契約、R2 有効化、バケット作成、キー発行、`wrangler login`。
2. 既存画像を `gallery:migrate` で送り、Worker をデプロイする。
3. 新URLで一覧・画像・カード・保存・X のプレビューを確認する。
4. GitHub Pages に最後の一度だけ、転送サイトをデプロイする。`/gacha/` と `card/<id>.html`（既存分すべて）から新URLへ転送する。カードには X 用メタタグも残す。トップの `#` 以降も引き継ぐ。
5. `deploy-gallery.yml` を削除し、Pages の設定は残す（配信は続く）。
6. 画像と manifest を git の追跡から外し `.gitignore` に入れる。**手元のファイルは消さない**。

4〜6 は公開サイトや git に影響するので、実行直前に改めて確認する。問題があれば手順4の前までは GitHub Pages がそのまま動く。

## 確認済みの事実・注意

- manifest は 176 件、手元と git にある画像は 174 枚。画像の無い 2 件は移行時に除外し、id を報告する。
- 現在の作業ツリーには未コミットのギャラリー変更（宝石・ハロウィン関連）がある。`gallery:deploy` は手元の状態をそのまま出すので、デプロイ前に内容を確認する。
- 画像の元データは git から外れるため、R2 と手元の 2 か所になる。

## テスト

Worker（各パス、404、メソッド、キャッシュ）、公開（順序、途中失敗、未公開を含めない、欠損、409）、ツイートリンクの基準URL、転送ページ生成。R2 はモックする。既存テストは新仕様に合わせて更新する。

## 実装者に任せること

ファイル分割、関数名、並列アップロード数、転送ページの文面。
